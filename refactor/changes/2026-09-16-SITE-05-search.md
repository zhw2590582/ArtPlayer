## 实际问题与修改

旧搜索能返回结果，不能把 flexsearch peer 警告写成搜索已失效。浏览器复现 Enter
导航后触发表单原生提交，URL 多出 `?` 且整页重载；有输入时 Escape 无法关闭。
新增回归在未修复构建上中英文各失败一次。保留当前第三方插件的索引、结果 URL、
模板和 CSS，通过包内 `build/search.ts` 在 Vue 编译前修复交互：取消表单默认提交，
按实际可见结果次序导航；无结果 Enter 不跳转；查询变化重置选择；Escape 关闭并
恢复按钮焦点。输入法组合键不触发选择，输入框等待 Vue DOM 更新再聚焦。
快捷键监听有卸载清理，异步索引导入有卸载守卫；加载前输入不读取未初始化索引。
卸载守卫属于本次源码修正，当前浏览器用例没有单独模拟组件卸载，不扩大验证结论。

适配器校验安装包组件的完整 SHA-256，统一 CRLF/LF 后要求每项补丁恰好匹配一次。
升级第三方必须人工复核补丁，不能只改哈希。既有第三方代码及署名留在原包，不复制
到自有源码、不修改 node_modules。首次实现遗漏 CRLF 匹配，随后聚焦回调排在 DOM
更新之前，均被测试捕获并修复；两个失败阶段的完整报告保留。最终没有放宽断言、
超时或加自动重试。播放器运行时、声明及公共分发 API 不变。

文档站 devDependency flexsearch 从 0.8.158 对齐到 0.7.43，满足插件的 ^0.7.31；
插件自身内置索引实现，peer 对齐不冒充索引或中文分词改进。原有精确 token 行为
保留，不承诺任意中文子串匹配。VitePress 未启用的托管 Algolia/search-insights
依赖仍有 peer 警告；本地搜索验收不代表托管提供方可用，不为消除警告引入服务依赖。

Yarn workspace add 曾忽略根级 dom-webcodecs resolution，根级 install 恢复了已批准
的 0.1.19；一次写锁文件出现 UNKNOWN，原命令重跑成功。最终锁 diff 仅 flexsearch
一个直接选择器，未带入无关 SDK 类型变化。唯一根 yarn.lock、根 resolution 保留。
