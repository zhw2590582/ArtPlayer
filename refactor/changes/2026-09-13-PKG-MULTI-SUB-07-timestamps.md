# PKG-MULTI-SUB-07 内嵌时间戳与显示层修复

九份历史实现已复现 `<00:02.000>` 被包装成字符串并输出 `<NaN:NaN.NaN>`。
本次保留数字 TimestampNode，处理顶层与嵌套节点，在有效的 VTT class 节点中承载
时间戳。解析树仍不可变，重复选择/reset 不积累包装；文本、标签和轨序的原回归保留。
私有 WrappedNode 现在与 CueNode 一样要求数字时间戳，编译负例从 8 项增为 9 项。

## 原生与自定义字幕层

直接输出有效时间戳后，Chromium 中的发布/候选核心都把 `<00:02.000>` 显示成文字。
这不是测试超时或资源加载失败，最初两个失败断言及截图/trace 已保留。
因此新增 caption.ts，在既有 subtitleAfterUpdate 事件后处理插件生成的专用标记。

- 原生 WebVTT 中的 `<c.artplayer-multiple-subtitles-timestamp>` 是合法 class 节点，
  其中的数字时间戳仍解析为 processing instruction，cue.text 不被显示层修改。
- HTML 不会把 `<c.class>` 与 `</c>` 配对，后面的字幕可能成为该元素的子节点。
  直接删除标记曾导致后文丢失；已通过真实浏览器复现并修正为移除前导时间指令、
  将其余子节点移回父层。对应失败报告保留，最终断言检查前后文字。
- 不对整段文字做时间戳正则删除。仅处理专用标记中的前导指令，普通用户文字和
  原有 `.art-subtitle-<name>` CSS 钩子保留。public cue.text 修改产生的字面量标签
  有真实浏览器回归，清空/reset 后正常恢复原字幕。
- 注册的监听器由当前 lifetime 管理，失败/销毁时移除；已有资源测试改为检查所有
  监听器集合为空。没有增加新公开选项、返回值或事件，不改变逐 cue 显示策略。

通过源码/main/legacy 与发布/候选核心，在 Chromium/Firefox/Windows WebKit 重跑。

## 独立发现与后续边界

又复现 `&lt;`、`&gt;`、`&amp;` 的多余分号，新增 MULTI-SUB-ENTITY-01，由 05 处置。
本任务不改 vendor；最终字面量显示测试通过公开 cue.text 修改隔离显示层，明确不代表
该实体解码缺陷已修复。额外分号的初始六个浏览器失败记录保留。
