## 设置导航：减少重复 DOM 工作

ENG-11 提交 5efc7f76 后恢复 doing。本阶段修改两个生产 TS 模块，不改变公共入口、回调、点击语义或声明。`keyboard.ts` 在读取条目和布局前排除无关按键；`keyboard-focus.ts` 为仍在活动面板内且可聚焦的 preferred 元素直接复核可用性，免去第二次全表扫描。若元素失效或只是包装节点，仍走原来的后代/选中项回退路径。每次按键仍重新读取条目，不跨事件缓存。断开、禁用、inert、无布局盒的元素先被排除，再读取计算样式。

40 个原生按钮的真实 Chromium 修改前证据显示：正常向下导航调用两次 querySelectorAll、80 次 getComputedStyle；修改后三引擎均为一次扫描、41 次样式读取。无关字符键从一次扫描/39 次样式读取变为零。浏览器测试还验证即时隐藏、inert、原生 disabled、tabindex=-1、恢复和公开 remove 后的实际焦点。记录的是操作次数，不据此估算毫秒收益。原有嵌套面板、更新失败恢复、原生范围、暂停作用域等回归保留。

构建后的现代包为 208030 raw / 58429 gzip9 字节；与 ENG-08 的 207875 / 58374 相比增加 155 / 55 字节。legacy 为 212211 / 59683，ESM 为 361484 / 77137。该小幅代码成本换取避免重复扫描，不能算作体积优化；ENG-PERF-01 仍 open。架构说明同步到包内 ARCHITECTURE.md。产物全部由正式 build 和 build:i18n 生成，没有手改产物或公开声明。

新安装包 run-UElxNR 的三引擎配对均完整，54 次候选资源清理探针通过。Chromium 第一组 core/chapter 销毁分别增加 3.1/2.5 ms，第三组 chapter 构造增加 2.8 ms；WebKit 第一组 chapter 销毁从 71 到 98 ms，其他组未重复该销毁信号；Firefox 本轮没有计时信号。固定计时夹具使用默认关闭的设置面板，不能把这些波动归因于本次导航路径。原始样本保留，ENG-PERF-02 扩展为构造及销毁计时待复核，门槛不变。

## 构造布局测量与最终核心阶段验收

两次真实 Chromium CPU 采样将默认构造热点定位到 control/layout.ts 的同步 offsetHeight 读取。
支持 ResizeObserver 时现在使用其首次布局通知，在构造剩余 DOM 写入后测量；旧环境立即测量，
显式 resize 仍同步。修改前的原生 observer 探针稳定记录一次同步读取，修改后为零，三引擎
15 项初始布局、fallback、窄屏/字幕位置和首次通知前销毁检查通过。最初的 fallback 测试在字幕
CSS 过渡未结束时断言最终位置，已改为等待实际状态，保留原失败报告，没有改变位置门槛。

两次修改后 CPU 采样不再在构造栈出现该 update 热点。诊断脚本已保存到
refactor/scripts/profile-core-layout.mjs，明确限定为 Chromium 未压缩源码构建的带分析器定位，
不是新旧性能门槛。Chromium 销毁采样主要落在原生 load 和 DOM 移除；保留释放顺序，不能将其
