# MOD-01 Bun 安装评估：保留 Yarn

已完成固定 Bun 1.4.2 的仓库外安装评估，结论是不采用。公开 API、生产源码、
根 yarn.lock、Node 运行时与 bundler 均未改变；新增 test:bun-install 和四个职责
独立的审计/比较脚本，模块地图与复跑步骤见 [维护文档](../bun-evaluation.md)。

## 实际验证

源提交 ddf3d6ccbc2fa7a3fa1a25c2b935b9d7045cee5c，Windows x64，Node 24.21.0、
Yarn 1.22.22、Bun 1.4.2。首次 Bun 冻结迁移因锁变更失败，报告保留；另一个
干净目录的普通迁移及生成锁后的冻结复装通过，后者依赖图/锁未变。

两边独立安装后均通过 2,906 项 Node 单元测试、415 个 TS 生产文件及公开/精确
消费者检查、完整 ci:build（含 21 库、声明、i18n、文档及五项导入测试）。
根固定工具相同，但 Algolia/Rollup 等传递解析、peer 与安装脚本策略不等价。
资源审计 92 对 90 个；构建清单各 534 文件中 448 完全相同，29 同路径改变、
两边各 57 独有路径均在文档站。库输出/声明相同不代替整套工具链等价。

新增两项审计回归通过，覆盖借用祖先 node_modules、内置同名 npm 包、嵌套依赖、
可选 peer 与资源指纹。修正审计器把 buffer 等误当内置模块漏报的问题，之后重新
生成两套图；不将修正前的包数量用于正式结论。scoped ESLint、严格工具链及计划
检查通过。完整日志路径与 SHA-256 见 [机器证据](../baselines/bun-install-validation.json)。

## 边界与恢复

初步 checkout 位于仓库内，发现可能借用父目录依赖后改用 OS 临时目录；初步日志
保留。正式 Yarn 复用下载缓存，Bun 初装为冷缓存，不提供速度提升比例。安装依赖
钩子没有全部禁用，也没有对 Bun 屏蔽的 less/nx 钩子强制 trust。没有改变全局 Bun。

此任务只作安装采用决策，不声称 Bun 浏览器、跨平台、真机或 npm 发布验收通过。
仍由 MOD-05 汇总工具链与性能决策。移除本任务脚本及文档即可撤销工程改动；
隔离 checkout/缓存清理须按维护文档核对归属，不影响工作区现有 node_modules。
任务独立本地提交后运行提交审计；未推送、部署或发布。
