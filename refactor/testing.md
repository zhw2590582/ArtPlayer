## 基线与差分

优先复用仓库现有 HTML 和在线编辑器，入口清单及任务归属见 [docs 页面与编辑器测试](docs-browser-testing.md)。执行前固定 prod 存储状态、实际脚本路径和构建来源；现有文档 smoke 不代替异步媒体断言。

正式浏览器基础设施建成前，BASE 任务以固定旧包、最小可重跑探针和已有页面采集，再由 ENG 接入自动化；具体启动、契约覆盖映射和文档包验收分类见 [执行门槛](execution-gates.md)。

1. 基线产物来自 BASE-01 固定的发布版本，保存 tarball integrity、源码 SHA、工具版本和样本信息。
2. 同一测试对旧产物和候选产物运行，比较公开结果、事件 trace、属性描述符和 DOM 状态。
3. 不使用整个 minified bundle 的文本相等作为 API 兼容证据。
4. 已确认缺陷使用单独用例记录“旧版本复现，候选修复”；差分例外必须有变更记录，不能一键更新全部快照掩盖回归。
5. 接口、类型与行为三项分别验收。只有类型检查通过不能证明运行时正确。
6. 起步先验证核心与试点，各包迁移前补齐自身发布基线。历史失败、候选回归和缺少环境分开，执行 ENG-10 的失败台账及逐模块门槛，不以全仓库初始全绿作为启动条件。

## 媒体样本

优先复用仓库中许可明确的本地 MP4/WebM/VTT/SRT/ASS；补充短 HLS/DASH、音轨/清晰度变化、无音轨、空字幕、损坏内容、慢响应和中断样本。媒体服务支持 Range 与受控错误。不要让公共直播 URL 的可用性决定 PR 是否通过。

浏览器不能解码特定样本时，要区分浏览器/codec 能力和播放器回归。需要实际支持的路径不能静默 skip；可选能力的 skip 必须有原因，设备验收在发布清单中保持待完成。

## CI 分层

用户已明确要求增强 GitHub CI/CD，当前 workflow 问题、目标矩阵、报告和实现任务见 [GitHub CI/CD 规范](github-ci-cd.md)。本地测试通过、workflow 静态检查、真实 Actions 通过分别记录。

| 触发 | 内容 |
| --- | --- |
| 每次 PR | 固定安装、只读 lint、类型、受影响单元/生命周期、核心浏览器 smoke、受影响发布包检查 |
| 核心或共享构建改变 | 全部 22 包构建/类型检查，旧插件对候选核心的回归，扩展浏览器矩阵 |
| 定期或候选发布 | 完整浏览器组合、压力/资源、性能、外部 SDK 与真机清单 |
| 发布前 | 干净环境完整 CI、tarball 消费、新旧组合、文档站、回退演练 |

快速检查必须存在依赖映射；无法确定受影响范围时运行完整核心及生态检查，不仅按文件名选择测试。

ENG-02 先交付仓库内可执行的 CI 配置；GitHub required checks 的实际设置属于外部状态，在发布准入时核实，不能把没有仓库管理权限变成本地测试框架建设的前置阻塞。尚未迁移的包保留历史失败台账，迁移包严格验收，所有受影响公开路径的候选回归仍阻止交付。

不要在媒体测试中靠固定 sleep 等待。优先受控事件/状态条件、固定样本和故障注入；对重试、偶发失败及 trace 有明确记录。真实设备缺失不阻止无关文档/本地候选准备，但始终阻止缺证据的相关能力通过发布验收。

## 证据要求

每次记录命令、HEAD、运行时与浏览器版本、样本、通过/失败/跳过数、报告路径和限制。报告持久化到可追溯的 CI artifact 或仓库中适量文本摘要，不只给开发机器临时路径。不提交大型录像/媒体/trace 到源码仓库。

必要门槛：没有新增未解释的失败，没有已知合法旧调用失效，关键资源在销毁后停止增长，发布路径存在且可加载。覆盖率报告先建立真实基线，再在 ENG 阶段按模块制定分支覆盖门槛；禁止用无意义测试堆数字。

性能门槛在 BASE-06 固定设备和统计方式后登记。若候选包 gzip 大小增长超过基线 5%，或主要测量中位数退化超过 10%，作为初始审查阈值触发调查，不能以一次波动判定回归，也不能以无测量声称优化。
